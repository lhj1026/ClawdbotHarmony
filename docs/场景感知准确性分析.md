# 基于5维物理信号的70场景感知准确性分析

> 本文系统分析情景智能框架中70个场景基于5维物理世界信号（位置、活动、时间、设备、环境）的规则引擎感知方案，重点论证每个场景能否达到极高准确率（precision）。核心原则：**准确性压倒召回率，不确定时归入未知场景。** 最近更新：2026-03-04

## 1. 问题定义与核心约束

### 1.1 可用信号空间

排除身体（需穿戴设备）和日程（需日历权限）后，系统基于以下5个维度感知用户场景：

| 维度 | 离散取值 | 传感器来源 | 可靠性 |
|------|---------|-----------|--------|
| **位置 (WHERE)** | 家、办公室、健身房、咖啡厅、商场、医院、机场、学校、公园、交通工具、未知 | 围栏/WiFi指纹/GPS | 围栏内高，围栏外依赖GPS精度 |
| **活动 (DOING)** | 静止、步行、跑步、驾驶/乘车、骑行 | IMU | 静止/步行/跑步高；驾驶vs乘车较难区分 |
| **时间 (WHEN)** | 黎明/上午/下午/傍晚/夜晚 × 工作日/周末 | 系统时钟 | 完全可靠 |
| **设备 (DEVICE)** | 充电中、低电量、已连WiFi、仅蜂窝网络 | 电池/网络API | 完全可靠 |
| **环境 (ENVIRONMENT)** | 安静、嘈杂、户外、室内 | 环境音插件 | 中等（取决于麦克风权限和算法） |

此外，StateTransitionTracker 提供**时序转移特征**（前序围栏、围栏变化、前序运动状态、转移持续时间、当前状态停留时间、近一小时转换次数、是否常规路线、转移方向），这些时序特征对转移类场景至关重要。

### 1.2 准确性优先原则

本方案要求的是**极高精确率（precision）**而非高召回率（recall）。具体含义：

- 当系统判定用户处于场景X时，用户实际处于场景X的概率需要 **>90%**
- 当信号组合存在歧义（多个场景共享相同信号指纹）时，**必须归入"未知场景"**
- 宁可漏判（用户处于某场景但系统未识别），不可误判（系统声称是某场景但实际不是）

### 1.3 信号指纹唯一性——核心挑战

每个场景本质上是5维向量空间中的一个区域。高准确率要求这些区域**不重叠**。问题在于：

- **位置="未知"** 涵盖了所有没有设置围栏的地点，这是一个巨大的模糊区域
- **活动="静止"** 是人类最常见的状态，大量场景共享这一信号
- **"家+静止"** 这一组合至少被12个场景共享（起床、做早餐、做饭、晚间放松、在家游戏、社交媒体、在线课程、考试复习、阅读、瑜伽、居家办公、睡前准备……）
- 没有日历数据，所有"会议相关"场景完全不可检测
- 没有应用使用数据，"数字活动"类场景（浏览社交媒体、听音乐、在线课程）不可区分

## 2. 分层分析：场景可检测性四级分类

基于信号指纹的唯一性，将70个场景分为四个等级：

| 等级 | 含义 | 精确率预估 | 适合策略 |
|------|------|-----------|---------|
| **A级：高置信可检测** | 信号组合在场景空间中（几乎）唯一 | >90% | 直接规则触发 |
| **B级：有条件可检测** | 需要附加条件（时间窗口、持续时间、转移序列）才能区分 | 70-90% | 严格规则 + 置信度阈值 |
| **C级：弱可检测** | 信号指纹与多个场景严重重叠，即使加严规则仍有较高误判率 | <70% | 建议归入上级场景或未知 |
| **D级：不可检测** | 缺少必要的信号维度（需日历/应用数据/穿戴设备） | N/A | 必须剔除或获取额外数据源 |

## 3. 逐场景分析

### 3.1 工作类（17个场景）

#### 场景1：早晨通勤（家→办公室，步行/驾驶）— A级

| 信号 | 要求 |
|------|------|
| 位置 | 围栏退出"家" → 围栏进入"办公室" |
| 活动 | 步行/驾驶/乘车 |
| 时间 | 上午 + 工作日 |
| 转移特征 | geofence_changed=1, prev_geofence=家, direction=休息→工作 |

**准确性判定：A级（高）。** 从家围栏退出后进入移动状态，在工作日上午，且最终到达办公室围栏——这一组合极为具体。关键前提：**用户已配置家和办公室围栏**。缺少围栏时退化为"工作日上午移动"，将与大量无关移动混淆，应归入未知。

#### 场景2：到达办公室（围栏进入）— A级

| 信号 | 要求 |
|------|------|
| 位置 | 围栏进入"办公室" |
| 转移特征 | geofence_changed=1 |

**准确性判定：A级（高）。** 围栏进入事件是一个精确的触发信号。进入办公室围栏就是到达办公室，几乎无歧义。

#### 场景3：会前准备（日历：即将开会）— D级

| 缺失信号 | 日历数据（已排除） |
|---------|----------------|

**准确性判定：D级（不可检测）。** 该场景的定义核心就是"即将开会"，这完全依赖日历数据。仅凭物理信号无法知道用户是否有即将开始的会议。

#### 场景4：会议中（日历：in_meeting，静止）— D级

**准确性判定：D级（不可检测）。** 同上，"会议中"需要日历数据。"办公室+静止"不能区分开会与其他办公活动。

#### 场景5：会后总结（日历：post_meeting）— D级

**准确性判定：D级（不可检测）。** 同上。

#### 场景6：📌 ~~午休开始~~ → **办公室午间外出** — ~~B级~~ → **A级 ↑**

| 信号 | 要求 |
|------|------|
| 位置 | 办公室围栏**退出** |
| 活动 | 步行/驾驶 |
| 时间 | 11:30-13:30 |
| 转移特征 | geofence_changed=1 |

**准确性判定：A级（高）。** 泛化后不再推测"午休"意图，而是客观描述"中午时段离开办公室"。围栏退出是精确的离散事件，加上中午时间窗口，信号指纹唯一。与场景9（傍晚离开办公室）通过时间窗口区分，无重叠。

#### 场景7：🔀 ~~午餐后返回~~ → **合并至场景2（到达办公室）** — ~~C级~~

**合并理由：** 此场景的信号指纹（办公室围栏重新进入 + 中午 + 步行→静止）与场景2（到达办公室）高度重合。无论是午餐归来还是外出开会回来，围栏进入事件是相同的。由场景2统一处理，通过时间上下文调整推荐内容。

#### 场景8：📌 ~~下午专注时间~~ → **办公室下午** — ~~C级~~ → **A级 ↑**

| 信号 | 要求 |
|------|------|
| 位置 | 办公室围栏内 |
| 活动 | 静止 |
| 时间 | 下午（12:00-17:00）+ 工作日 |

**准确性判定：A级（高）。** 泛化后不再声称用户在"专注"，而是客观描述"工作日下午在办公室"。这一信号组合唯一——与场景2（进入事件）、场景6（午间外出事件）、场景17（傍晚留守）通过时间窗口和事件类型完全区分。场景名称精确匹配信号指纹。

#### 场景9：离开办公室（围栏退出，傍晚）— A级

| 信号 | 要求 |
|------|------|
| 位置 | 围栏退出"办公室" |
| 时间 | 傍晚（17:00-20:00） |
| 转移特征 | geofence_changed=1 |

**准确性判定：A级（高）。** 傍晚时段离开办公室围栏是一个强信号。将时间限制放宽（不仅限傍晚）可能降低准确性（中午外出不等于下班），但傍晚退出是高准确的。

#### 场景10：晚间通勤回家（办公室→家，驾驶/乘车）— A级

| 信号 | 要求 |
|------|------|
| 位置 | 办公室围栏退出 → 家围栏进入 |
| 活动 | 驾驶/乘车 |
| 时间 | 傍晚 + 工作日 |
| 转移特征 | prev_geofence=办公室, direction=工作→休息 |

**准确性判定：A级（高）。** 与场景1对称，两个围栏间的定向转移在傍晚工作日时段是非常明确的通勤信号。

#### 场景11：📌 ~~居家办公~~ → **工作日居家白天** — ~~C级~~ → **A级 ↑**

| 信号 | 要求 |
|------|------|
| 位置 | 家围栏内 |
| 活动 | 静止 |
| 时间 | 工作日 + 上午/下午 |
| 设备 | WiFi连接 |

**准确性判定：A级（高）。** 泛化后不再推测"办公"意图，而是客观描述"工作日白天在家"。这一信号组合唯一——与场景26（周末早晨）通过工作日/周末区分，与场景22（居家傍晚）通过时间段区分。无论用户是远程办公、休假还是休息，系统只描述物理状态，不推测意图。

#### 场景12：客户拜访（未知位置，工作日，步行）— D级

| 信号 | 要求 |
|------|------|
| 位置 | 未知（无围栏） |
| 活动 | 步行 |
| 时间 | 工作日 |

**准确性判定：D级（不可检测）。** "未知位置+工作日+步行"是一个极其宽泛的描述，涵盖了去买咖啡、中午散步、逛街、办私事等一切工作日外出步行行为。客户拜访是一种商业意图，物理信号完全无法区分。

#### 场景13：📌 ~~出差出发~~ → **到达机场** — ~~B级~~ → **A级 ↑**

| 信号 | 要求 |
|------|------|
| 位置 | 机场围栏进入 |
| 转移特征 | geofence_changed=1 |

**准确性判定：A级（高）。** 泛化后不再推测"出差"意图，而是客观描述"到达机场"。机场围栏进入是精确的离散事件，几乎无歧义。至于出行目的（出差/旅游/接人），由推荐层根据其他上下文决定。

#### 场景14：会议/活动（未知，工作日，静止）— D级

**准确性判定：D级（不可检测）。** "未知位置+工作日+静止"覆盖了一切非围栏内的工作日静止场景。

#### 场景15：深夜加班（办公室，夜晚，静止）— A级

| 信号 | 要求 |
|------|------|
| 位置 | 办公室围栏内 |
| 活动 | 静止 |
| 时间 | 夜晚（21:00+）+ 工作日 |

**准确性判定：A级（高）。** 工作日夜晚仍在办公室，这是一个非常罕见且特定的信号组合。如果用户在夜晚21点之后仍然在办公室围栏内，几乎可以确定是加班。

#### 场景16：周末加班（办公室，周末）— A级

| 信号 | 要求 |
|------|------|
| 位置 | 办公室围栏内 |
| 时间 | 周末 |

**准确性判定：A级（高）。** 周末出现在办公室是非常明确的加班信号。极少有其他原因导致周末在办公室围栏内长时间停留。

#### 场景17：📌 ~~赶截止日期~~ → **傍晚留守办公室** — ~~C级~~ → **A级 ↑**

| 信号 | 要求 |
|------|------|
| 位置 | 办公室围栏内 |
| 活动 | 静止 |
| 时间 | 傍晚（17:00-21:00）+ 工作日 |

**准确性判定：A级（高）。** 泛化后不再推测"赶deadline"心理状态，而是客观描述"傍晚仍在办公室"。与场景15（深夜加班，21:00+）通过时间窗口明确区分。正常下班时间后仍在办公室围栏内，信号组合唯一。

### 3.2 生活类（23个场景）

#### 场景18：家中起床（家，黎明/上午，静止→步行）— B级

| 信号 | 要求 |
|------|------|
| 位置 | 家围栏内 |
| 活动 | 静止→步行（当日首次活动状态转移） |
| 时间 | 黎明/上午（5:00-9:00） |
| 转移特征 | time_in_current（静止）很长（整夜），transitions_last_hour低 |

**准确性判定：B级（有条件可检测）。** 关键在于能否检测到"当日首次从长时间静止转为步行"。如果用户整夜保持静止（time_in_current高，transitions_last_hour=0），然后在清晨突然开始步行，这几乎就是起床。但挑战在于：夜间上厕所也会产生短暂步行，需要设置最短步行持续时间阈值。

> **高准确率规则：** 家 + 清晨 + 从持续4小时以上的静止状态首次转移为步行 + 步行持续>2分钟。

#### 场景19：晨练（健身房/公园，上午，跑步/步行）— A级

| 信号 | 要求 |
|------|------|
| 位置 | 健身房/公园围栏 |
| 活动 | 跑步或步行 |
| 时间 | 上午 |

**准确性判定：A级（高）。** 上午出现在健身房/公园围栏内且处于跑步或步行状态，几乎可以确定是在锻炼。健身房本身就是一个高度具体的场所。

**合并理由：** "家+上午+静止"在工作日被场景11（工作日居家白天）完全覆盖，在周末被场景26（周末早晨）完全覆盖。"准备早餐"是具体家务意图，物理信号无法区分它与其他居家上午活动。

|------|------|

**准确性判定：A级（高）。** 在商场围栏内步行，几乎可以确定在购物或至少在逛商场。极少有人去商场长时间步行做其他事。

#### 场景22：📌 ~~在家做饭~~ → **居家傍晚** — ~~C级~~ → **A级 ↑**

| 信号 | 要求 |
|------|------|
| 位置 | 家围栏内 |

**准确性判定：A级（高）。** 泛化后不再推测"做饭"，而是客观描述"傍晚在家"。这一信号组合唯一——与场景11（白天）、场景25（深夜）通过时间段区分。原先与场景24（放松）、30（聚会）、55（游戏）的信号冲突通过合并彻底消除：它们都归入"居家傍晚"。

#### 场景23：📌 ~~外出就餐~~ → **到达餐厅/咖啡厅** — ~~B级~~ → **A级 ↑**

**准确性判定：A级（高，需围栏）。** 泛化后不再推测"就餐"意图，而是客观描述"到达餐厅/咖啡厅围栏"。围栏进入是精确事件。**前提：仅在位置命中围栏时触发**，无围栏时不触发（归入未知），保证极高准确率。

#### 场景26：周末早晨（家，周末，上午）— A级

| 信号 | 要求 |
|------|------|
| 位置 | 家 |
| 时间 | 周末 + 上午 |

**准确性判定：A级（高）。** 该场景定义本身足够宽泛——周末上午在家就是"周末早晨"，不需要区分具体在做什么。场景名称与信号指纹精确匹配。

> **关键洞察：** 此场景之所以准确率高，是因为它的定义与信号指纹刚好吻合。它描述的是一个物理状态而非用户意图。

#### 场景27：周末外出（公园/商场，周末，步行）— A级

#### 场景28：医院就诊（医院，静止）— A级

| 信号 | 要求 |
|------|------|

| 活动 | 静止 |

**准确性判定：A级（高）。** 在医院围栏内静止，几乎可以确定与就医相关（就诊、陪诊、体检）。医院是一个高度特殊的场所，很少有人无故长时间停留。

| 信号 | 要求 |
|------|------|

### 4.2 核心发现

**发现1：场景名称泛化是提升准确率的关键杠杆。** 通过将场景名称从"用户意图"（做饭、放松、游戏）改为"物理状态"（居家傍晚），同一信号指纹的准确率从C级跃升至A级。**根本原因：当场景名称恰好等于信号指纹时，精确率趋近100%。**

**发现2：位置围栏仍是准确性的基石。** A级场景中绝大多数依赖围栏信号。系统的准确性上限由**用户配置的围栏数量和质量**决定。

**发现3："家+静止"黑洞通过时间分片彻底解决。** 原先12个共享"家+静止"的场景，经泛化后分流至：工作日居家白天(11)、周末早晨(26)、居家午后(39)、居家傍晚(22)、居家深夜(25)、居家安静时段(49)——每个时段的信号指纹唯一，冲突消除。

**发现4：日历数据的缺失砍掉了整个"会议"维度。** 场景3/4/5（会前/中/后）完全依赖日历，仍为D级。

**发现5：转移类场景是准确率最高的类别。** 7个转移场景全部A级，围栏进出事件天然具有高准确性。

**发现6：11个场景通过合并消除。** 这些场景的信号指纹被其他泛化后的场景完全覆盖，独立存在会造成规则冲突。

### 4.3 对70场景方案的可行性结论

> **经泛化重命名后，70个场景中35个（50%）可达极高准确率，另有9个（13%）有条件可用。总计44个场景（63%）可纳入高准确率规则引擎，较泛化前（49%）提升29%。11个场景合并至同信号指纹的上级场景，14个场景因缺少必要信号维度仍不可检测。**

泛化后的策略：
1. **A级35个场景**作为核心规则集，直接触发
2. **B级9个场景**作为条件触发规则（需额外阈值和置信度检查）
3. **C级1个场景**（未知地点长时间停留）建议归入未知
4. **D级14个场景**标注为"需额外数据源"（日历/APP使用/穿戴设备）

## 6. 关键技术依赖与准确性要求

场景感知系统的整体准确率受限于底层传感技术的最短板。以下分析每项关键技术对场景系统的支撑作用、精度要求及失效影响。

### 6.1 技术依赖总览

| 技术 | 依赖它的场景数 | 精度等级要求 | 当前可靠性 | 失效影响 |
|------|--------------|-------------|-----------|---------|
| **地理围栏** | 31/44 (70%) | 极高：漏触发/误触发直接导致场景误判 | 高（WiFi指纹）/ 中（纯GPS） | **致命**：A级场景全面退化 |
| **IMU运动识别** | 28/44 (64%) | 高：静止/步行/跑步需>95%准确率 | 高（静止/步行/跑步）/ 中（骑行/驾驶） | 高：运动类场景全部失效 |
| **系统时钟** | 35/44 (80%) | 完全可靠 | 100% | — |
| **设备状态API** | 6/44 (14%) | 完全可靠 | 100% | 低：仅影响辅助信号 |
| **环境音分类** | 5/44 (11%) | 中：安静/嘈杂二分类>80% | 待验证 | 中：5个B级场景受影响 |
| **状态转移追踪** | 18/44 (41%) | 高：依赖底层围栏和IMU的质量 | 取决于底层 | 高：转移和持续时间场景失效 |

### 6.2 地理围栏（Geofencing）— 系统基石

**作用：** 70%的A级场景依赖围栏的进入/退出事件或围栏内判定。围栏是将"位置=未知"提升为"位置=家/办公室/..."的唯一机制。

**精度要求：**

| 指标 | 要求 | 原因 |
|------|------|------|
| 进入事件假阳性率 | <2% | 误进入围栏直接触发错误场景（如不在办公室却触发"到达办公室"） |
| 进入事件假阴性率 | <10% | 漏检可接受（归入未知），但频繁漏检降低用户体验 |
| 退出事件延迟 | <5分钟 | 过长延迟导致"离开办公室"场景滞后触发 |
| 围栏半径精度 | ±50m | 过小导致频繁进出抖动，过大导致跨场所误判 |

**实现方案与对比：**

| 方案 | 精度 | 功耗 | 适用场景 |
|------|------|------|---------|
| **WiFi BSSID指纹** | 高（室内可达房间级） | 极低（被动扫描） | 家、办公室、咖啡厅等有WiFi的固定场所 |
| **GPS围栏** | 中（室外±10m，室内±50-100m） | 高（持续GPS） | 公园、商场、医院等大型户外场所 |
| **WiFi+GPS混合** | 高 | 中 | 推荐方案：室内用WiFi，室外用GPS |

**关键风险：**
- GPS漂移（室内、高楼峡谷）可能导致围栏抖动 → 需要**滞后机制**（hysteresis）：进入需连续命中N秒，退出需连续离开M秒
- 用户未配置围栏时，所有位置相关场景退化为D级 → **冷启动引导**至关重要

### 6.3 IMU运动状态识别 — 核心信号

**作用：** 区分静止/步行/跑步/驾驶/骑行五类运动状态，是除位置外最重要的信号。

**精度要求（按活动类型）：**

| 活动 | 要求精确率 | 要求召回率 | 难度 | 依赖此状态的典型场景 |
|------|-----------|-----------|------|-------------------|
| **静止** | >98% | >95% | 低 | 办公室下午(8)、居家系列(11/22/25/39) |
| **步行** | >95% | >90% | 低 | 购物(21)、公园步行(32)、周末户外步行(58) |
| **跑步** | >90% | >85% | 中 | 晨练(19)、户外跑步(52) |
| **驾驶/乘车** | >85% | >80% | 中高 | 通勤(1/10)、长距离驾驶(36) |
| **骑行** | >85% | >80% | 中 | 骑行(60) |

**混淆矩阵关键风险：**
- **步行↔静止混淆：** 缓慢走动时（如在室内徘徊），IMU可能在步行和静止间震荡 → 需要**最短持续时间阈值**（如步行需持续>15秒才确认）
- **驾驶↔静止混淆：** 红灯等待、交通堵塞时可能误判为静止 → 需要**状态保持机制**（驾驶状态进入后，需连续静止>2分钟才切换为静止）
- **骑行↔驾驶混淆：** 低速骑行和低速驾驶的加速度模式相似 → 需结合速度（GPS）辅助

**关键实现要点：**
- 鸿蒙 `@ohos.sensor` 提供加速度、陀螺仪原始数据
- 分类器推荐：轻量决策树或小型CNN，窗口长度2-4秒
- 输出应为**概率分布**（如 {静止:0.7, 步行:0.3}），非硬标签，便于软匹配

### 6.4 环境音分类 — B级场景的区分器

**作用：** 提供安静/嘈杂二分类，是5个B级场景（49/54/59/62及辅助场景）的关键区分信号。

**精度要求：**

| 分类 | 要求精确率 | 容许的误分类方向 |
|------|-----------|----------------|
| **安静** | >85% | 嘈杂→安静误判（假安静）可接受度低：会在实际嘈杂时错误触发"安静"场景 |
| **嘈杂** | >80% | 安静→嘈杂误判（假嘈杂）较可接受：嘈杂场景触发条件更多，单一误判不致命 |

**实现挑战：**
- **麦克风权限：** 需要持续或周期性的音频采样，用户可能拒绝 → 需设计为**可选信号**，缺失时相关B级场景不触发
- **隐私保护：** 不应录制或存储音频内容，仅提取声压级（dB）和频谱特征 → 端侧实时处理，不上传
- **分类边界：** "安静"和"嘈杂"的阈值因环境而异（图书馆40dB vs 家中50dB均为"安静"） → 建议使用**相对阈值**或用户自适应基线

### 6.5 状态转移追踪（StateTransitionTracker）— 时序推理层

**作用：** 在底层围栏和IMU之上提供时序推理能力——围栏变化检测、状态持续时间、转移频率、常规路线识别。

**精度要求：** 本身为纯软件逻辑，准确性完全取决于底层信号质量。关键指标：

| 特征 | 依赖 | 精度传导 |
|------|------|---------|
| `geofence_changed` | 围栏进出事件 | 围栏误触发 → 虚假转移 |
| `time_in_current` | 系统时钟 + 状态变化检测 | 可靠 |
| `transitions_last_hour` | 状态变化事件流 | 围栏/IMU抖动 → 虚高计数 |
| `is_routine` | 历史路径统计 | 需至少2-3周数据积累 |

**关键风险：** 围栏抖动（反复进出）会导致 `transitions_last_hour` 虚高、`geofence_changed` 频繁误触发 → 必须在围栏层实现滞后机制。

### 6.6 技术准确性的系统性影响

> **核心结论：** 地理围栏的质量决定了系统的天花板。围栏精度不足时，70%的A级场景退化；IMU精度不足时，64%的场景受影响。环境音分类是可选增强项，其缺失仅影响5个B级场景。

**优先级排序：**

| 优先级 | 技术 | 理由 |
|--------|------|------|
| **P0** | 地理围栏（WiFi指纹+GPS混合） | 系统基石，70% A级场景依赖 |
| **P0** | IMU运动识别 | 64%场景依赖，且为围栏的补充区分维度 |
| **P1** | 状态转移追踪 | 纯软件层，精度取决于P0 |
| **P2** | 环境音分类 | 可选增强，仅影响B级场景 |

## 8. 总结

经过场景名称泛化，70场景方案的可用性大幅提升：**A+B级场景从34个（49%）增至44个（63%），A级场景从23个翻升至35个**。核心方法论是：

> **场景名称 = 信号指纹 → 精确率趋近100%**

当场景停止描述"用户意图"（做饭、放松、摄影）而改为描述"物理状态"（居家傍晚、周末户外步行），信号指纹与场景定义完全吻合，准确率问题从根本上消除。

**泛化后的系统架构：**
- **35个A级场景**：以围栏事件、时间分片、运动状态为核心的高置信规则集
- **9个B级场景**：需额外条件（持续时间、环境音、常规路线）的条件触发规则
- **11个合并场景**：信号指纹被上级场景完全覆盖，不再独立触发
- **14个D级场景**：需日历/APP使用/穿戴设备数据，当前不可检测
- **1个C级场景**：建议归入未知

**仍需额外数据源的关键缺口：**
1. **日历数据**：可激活场景3/4/5（会前/中/后），这是最高价值的缺口
2. **APP使用数据**：可区分数字活动（游戏、社交媒体、在线课程）
3. **穿戴设备**：可检测睡眠、心率等身体状态
